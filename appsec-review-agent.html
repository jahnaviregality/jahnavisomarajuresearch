01 / Research signal

The question beneath the system

How can pull-request security review separate reliable detection from flexible explanation while remaining auditable and reproducible?

Abstract, condensed from the supplied source

Security review of pull requests is often manual, inconsistent, and dependent on reviewer expertise. The paper proposes the AppSec Review Agent: a five-agent architecture with an Orchestrator, three deterministic specialist agents for static analysis, dependency-CVE lookup, and secret scanning, and an LLM Reasoning Agent supported by three memory tiers. Agents communicate through the Model Context Protocol (MCP).

02 / Context

Why this work exists

A monolithic LLM must parse code, recall vulnerability patterns, reason about exploitability, prioritize issues, and phrase a response in one undifferentiated pass. The paper identifies confirmation bias, inconsistent repeated runs, and brittle point-to-point integrations as design problems.

05 / Evidence

What the paper actually reports

The case study supports the intended division of labor: the vulnerability was caught before the LLM call, while the LLM contributed explanation and a parameterized-query suggestion.

Available evidence

One worked case study reports deterministic detection of unsanitized user input concatenated into a SQL query and no new dependencies or secrets. Benchmark-scale quantitative evaluation is explicitly scoped as a next phase.
